## Overview

This pipeline provides the R6000 (NVIDIA RTX PRO 6000 / Blackwell) benchmark scaffold for **Qwen3.6-9B-Dense** across three quantization paths:

| Path | Quant | Runtime | Target Device | Size (est.) |
|------|-------|---------|---------------|-------------|
| BF16 baseline | BF16 | Lynn Engine | RTX 4090/5080 (24 GB+) | ~18 GB |
| Q4_K_M reference | Q4_K_M | llama.cpp / GGUF | Cross-platform (Mac/NVIDIA) | ~5.2 GB |
| W4A16 NVFP4 | W4A16 / NVFP4 | Lynn Engine | RTX PRO 6000 / B200 (SM100+) | ~5.5 GB |

**Product positioning:**
- **9B Dense** = endpoint / 16G VRAM branch candidate. Small enough for edge deployment, large enough for useful quality.
- **Q4_K_M** = Mac / Apple Silicon / llama.cpp path. No NVIDIA dependency.
- **W4A16 / NVFP4** = NVIDIA Blackwell serving path. Lynn-native packed decode + TensorCore MMA.

## Usage

### 1. Dry-run (default)

```bash
bash scripts/r6000_qwen36_9b_dense_matrix_pipeline.sh
```

Prints all commands without executing. Validates model path detection.

### 2. Execute with real paths

```bash
export MODEL_DIR=/data/models/Qwen3.6-9B-Dense
export OUTPUT_DIR=./r6000_9b_reports
export DRY_RUN=0
export LLAMACPP_BIN=llama-bench
export LYNN_ENGINE_BIN=lynn-engine-bench

bash scripts/r6000_qwen36_9b_dense_matrix_pipeline.sh
```

### 3. Summarize reports

```bash
python3 scripts/summarize_qwen36_9b_r6000_reports.py \
    --schema reports/qwen36_9b/qwen36_9b_dense_matrix_schema_v1.json \
    --reports ./r6000_9b_reports \
    --out docs/QWEN36_9B_R6000_PIPELINE_20260518.md
```

The summarizer:
- Reads `bf16_report.json`, `q4km_llamacpp_report.json`, `w4a16_nvfp4_report.json`
- Merges metrics back into the release matrix schema format
- Outputs a Markdown preview with status badges
- **Handles empty/missing reports gracefully** — outputs PENDING scaffold

## Stage Details

### Stage 1: BF16 Baseline

- **Purpose:** Quality ceiling. All quantized variants compared against this.
- **Command:** `lynn-engine-bench --model ${MODEL_DIR}/bf16 --benchmark mmlu,gpqa,single_tps,concurrent_tps`
- **Expected fields:** MMLU, GPQA, single TPS, concurrent TPS
- **Status:** PENDING (no model inference in scaffold)

### Stage 2: Q4_K_M llama.cpp

- **Purpose:** Cross-platform reference baseline. Mac endpoint path.
- **Command:** `llama-bench -m ${MODEL_DIR}/gguf/qwen3.6-9b-dense-q4_k_m.gguf --output-format json`
- **Expected fields:** MMLU (via perplexity), single TPS
- **Status:** PENDING

### Stage 3: W4A16 NVFP4 Lynn-native

- **Purpose:** NVIDIA Blackwell optimized path. Packed NVFP4 decode.
- **Command:** `lynn-engine-bench --model ${MODEL_DIR}/w4a16_nvfp4 --benchmark mmlu,gpqa,single_tps`
- **Expected fields:** MMLU, GPQA, single TPS, concurrent TPS
- **Status:** PENDING

## Safety Guarantees

- **DRY_RUN=1 by default.** No commands execute unless explicitly set to `0`.
- **No downloads.** Pipeline assumes models are already present at `MODEL_DIR`.
- **No deletions.** Output directory is created if missing; existing files are never removed.
- **Missing-path tolerant.** If a model path is not found, the stage is skipped with a warning.
- **Empty-report tolerant.** Summarizer produces a valid scaffold even with zero report files.

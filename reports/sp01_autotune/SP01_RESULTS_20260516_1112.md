# SP-01 Triton Autotune Results · Spark sm_121 · 2026-05-16 11:12

## TL;DR

**SP-01 autotune wins +5.5-6.0% TPS on Spark sm_121 over the production static config.**
Same kernel math; only `(BLOCK_INTER, BLOCK_HIDDEN, num_warps, num_stages)` differ.
Stays well short of SGLang FP8+MTP — gap closure needs SP-02 spec decoding (and
possibly SP-04 expanded BLOCK_INTER sweep).

```text
Lynn 27B NVFP4 baseline   single 43.33 / mixed 43.26 mean
Lynn 27B NVFP4 + SP-01    single 45.92 / mixed 45.64 mean    (+6.0% / +5.5%)
SGLang FP8+MTP 35B        single 43.44 / mixed 49.97 mean    (peak 62.51)
Gap remaining             mixed -4.33 / peak -16.61 TPS to SGLang
```

## Methodology

- Same hardware (Spark GB10 sm_121), same model
  (`lynn-27b-variable-recovery-step5000-nvfp4-final`), same env stack
  (`scripts/spark/run_27b_nvfp4_server.sh`), production native_fast_2d backend.
- Bench harness: `benchmarks/sp01_tps_bench.py` (this commit).
- 3 single-stream 300-token + 20 mixed-prompt 200-token via `/v1/chat/completions`.
- Temperature 0, greedy, diverse Chinese prompts (no radix prefix dedup bias).

## What This Confirms

1. **Triton autotune is a real lever on Spark sm_121** — counter to Codex P53's
   "no free 15 TPS in current Triton shape" conclusion (which only tested
   scale-hoist + LUT decode expression mods, not config sweeps).
2. **The production static `(block_inter=8, block_hidden=64, num_warps=4)` was
   not the Spark-optimal** — autotune found something better.
3. **+6% in pure launch-config tuning suggests more headroom** if we widen the
   sweep to include BLOCK_INTER ∈ {2, 4} (Codex P55 R6000 tile_inter=2 result).

## Open Question

Microbench (`benchmarks/sp01_sm121_autotune_microbench.py`) **OOM'd the server**
because it tries to load the model again while the production server is up
(both compete for the same 96GiB unified mem). To recover autotune-picked
configs, must either:

- (a) Run microbench with server stopped
- (b) Add an in-process dump endpoint to the server to expose autotune cache

Deferred — TPS gain is the result that matters, not the picked configs.

## Next Moves Decided

- **SP-01.5 expanded sweep** (5 min code, 15 min total): add BLOCK_INTER ∈ {2, 4}
  candidates. Codex's R6000 P55 tile_inter=2 was 8.6-14.1% local; even half of
  that on Spark = another +3-5% TPS, additive.
- **SP-04 native CUDA tile_inter=2 port** (later): if Triton can't reach Codex
  numbers, port the actual `gate_up_silu_tile_inter_scalar` CUDA C++ from
  R6000. But Spark CUDA build infra is unverified for sm_121 — leave as
  fallback.
- **SP-02 N-gram spec decoding** (the big lever): closes peak gap to SGLang
  via prompt n-gram lookahead + multi-token verify. ~3-5h engineering.
  Conservative 1.2× on top of SP-01 = 54.8 mean — **beats SGLang 49.97 mean**.
